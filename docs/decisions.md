# 决策记录

按时间倒序。每条写清楚决定了什么、为什么、带来哪些约束。新决定追加在最上面，旧决定被推翻时标注“已被 #N 取代”，不删除。

## #5 数据源原则：只用官方 API、允许转载的 feed，和不绕反爬的低频抓取

- 日期：2026-11-17
- 决定：
  - 数据优先来自官方 API（Best Buy、Woot、eBay、Walmart Affiliate）和条款允许转载的 feed（DealNews）。
  - 网页抓取只用于没有 API 的站点，并且未登录、低频、不绕验证码、不用住宅代理。
  - Slickdeals 只用于内部规则匹配，未获授权前不在门户展示。
  - 不再使用 Reddit。
- 原因：
  - 商业化后，数据源条款按商业用途算。
  - 反爬对抗会带来封 IP 和合同纠纷风险。
  - Reddit 的 RSS 已于 2026-11-13 停止，公开 Data API 将于 2027 年 3 月关闭。
- 约束：
  - 每接一个来源，先读条款并把结论记进 `sources` 表。
  - Best Buy API 数据最多缓存 72 小时，并注明来源。
  - Amazon 价格只能来自 Creators API（见 design.md 合规一节）。

## #4 架构：单台 VPS + 家用采集节点

- 日期：2026-11-17
- 决定：
  - 一台 VPS 用 Docker Compose 跑 Postgres、FastAPI 后端、工作进程和 Caddy。
  - 只认住宅 IP 的站点（目前是 Micro Center）由家里现有的 openbox-monitor 容器抓取，结果通过 HTTPS 推给服务器。
- 原因：
  - 采集要长时间运行，并且需要稳定的出口 IP。
  - 服务器的机房 IP 不去碰容易被拦的站点。
  - 家用节点主动推送，不需要对外开放端口。
  - 成本最低，并且沿用现有 Python 代码。
- 约束：
  - 家用节点和服务器之间用带签名或 token 的 HTTPS 接口。
  - 家用节点离线时，对应来源标记为“过期”，不能判定商品下架。

## #3 技术栈：Python（FastAPI + SQLAlchemy）+ Postgres，前端先服务端渲染

- 日期：2026-11-17
- 决定：
  - 后端用 FastAPI 和 SQLAlchemy，数据库用 Postgres，队列用 Dramatiq 或 Postgres 队列。
  - 前端先用 Jinja + htmx 做服务端渲染。
  - 邮件用 Resend，收款用 Stripe，注册防机器人用 Cloudflare Turnstile。
- 原因：
  - 现有 openbox-monitor 是 Python 写的，抓取和解析代码可以直接复用。
  - 服务端渲染出 MVP 最快。
- 约束：
  - 不引入 AGPL、SSPL 或禁止商用许可证的依赖。

## #2 开放注册

- 日期：2026-11-17
- 决定：门户对公众开放注册，不走邀请制。
- 原因：增长和联盟计划申请都需要一个公开、可访问的网站。
- 约束：
  - 注册和登录要有 Turnstile 验证、按 IP 和邮箱限速，并拦截一次性邮箱。
  - 套餐配额：规则数、每日邮件数、提交链接数都有上限。
  - 抑制名单在删除账户后也保留。
  - 上线时邮件直接用 Resend Pro，因为免费档每天 100 封不够。
  - 上线前要有服务条款和隐私政策。

## #1 商业化

- 日期：2026-11-17
- 决定：项目按商业产品做，收入来自联盟佣金和 Pro 订阅。
- 原因：覆盖数据和发信成本，并为付费数据源（如 Keepa、更大的发信量）提供预算。
- 约束：
  - 依赖许可证：避开 AGPL、SSPL 和禁止商用的许可证；PriceBuddy 只参考思路。
  - 链接安全检查：Google Safe Browsing 只限非商业用途，改用 Web Risk。
  - 邮件：deal 提醒按 CAN-SPAM 算商业邮件，要有实际通信地址、一键退订和联盟披露。
  - 联盟链接：链接旁披露（FTC），各联盟计划的条款逐条遵守。
  - 公司：建议成立 LLC，Stripe 和联盟收款都用公司名义。
  - 仓库：建议保持私有，不加开源许可证。
